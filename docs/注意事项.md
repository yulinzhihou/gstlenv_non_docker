# 注意事项

## 一、端口与防火墙（默认值对齐 gstlenv env.sample）

| 端口 | 用途 |
|---|---|
| 3306 | MySQL（游戏服务端连接数据库，gstlenv 对外映射 33061，本机收敛用 3306） |
| 13580 | 登录网关（gstlenv LOGIN_PORT） |
| 15680 | 游戏网关（gstlenv SERVER_PORT） |
| 21818 | billing 验证（gstlenv BILLING_PORT） |
| 51888 / 61888 | web 访问 / web GM（gstlenv WEB_PORT / WEB_GM_PORT） |

**云服务器**：需在控制台安全组放行以上端口；**本机**：`firewall-cmd` / `ufw` / `iptables` 放行。
> 安装器会自动关闭 selinux（若开启），避免 32 位进程加载驱动被拦截。

## 二、安全提醒

1. **数据库密码**：默认 `123456`（对齐 gstlenv），公网环境请安装时修改为强密码（`TLBB_DB_PASS=新密码 bash install.sh` 或 `setconfig` 改）。
2. **reset 会清空所有玩家数据**：执行前务必 `backup`。
3. **remove 会将 /tlgame 迁移为 /tlgame-时间戳 并移除命令与 /root/.gs**：数据保留在迁移目录中，确认不再需要后手动删除。
4. **公网开服风险**：请勿将 root 密码、数据库密码明文写在客户端配置中；建议用专用账号连接数据库（安装器已建 `gs` 账号，密码与 root 同默认 123456）。

## 三、系统兼容注意事项

### RHEL 系
- **CentOS 5**：已 EOL，仅支持 64 位；使用阿里云 centos-vault 5.11 归档源（http）。若 vault 源失效，离线 rpm 兜底（offline/el5/）可保证 unixODBC + 驱动安装。
- **CentOS 6/7/8**：已 EOL，自动切换 vault 归档源；若源失效请先 `yum clean all` 再重试。
- **数据库（不用 MariaDB）**：
  - el5/el6：MySQL 5.1（yum vault 归档）
  - el7：MySQL 5.1.73（内置离线包 MySQL.tar.gz，无网络可用）；如需 5.7 指定 `TLBB_MYSQL_VERSION=57`
  - el8：MySQL 5.7（默认，官方源阿里云/华为云镜像；可切 8.0）
  - el9：MySQL 8.0（官方源；64 位源端引擎需自行替换 SQL 和 ini，对齐 gstlenv 编号4）
  - el10：MySQL 8.4（官方 8.0 无 el10 包；官方/清华/腾讯/阿里镜像 el10 均有 8.4 仓库；SQL 与认证行为同 8.0，复用 mysql80 数据包）
- **MySQL 5.7/8.0/8.4 官方源**：自动探测 官方 repo.mysql.com → 清华 TUNA → 腾讯云 → 阿里云 → 华为云，兼容官方嵌套目录与国内镜像扁平目录（`mysql-8.4-community-el10-x86_64`）；el10 上指定 8.0 会自动切换 8.4；源文件 `/etc/yum.repos.d/mysql-community.repo`（gpgcheck=0 便于内网/离线）。
- **32 位兼容库**：与内核/glibc 版本强绑定，无法通用离线，必须走系统源。若系统源失效需先修复源（本包已自动处理 EOL 归档）。**系统源 makecache 失败会自动依次换用 腾讯云/华为云/清华 镜像重试**（部分网络对某镜像大 metadata 下载会超时/断流，表现为小体积源正常而 BaseOS/AppStream 失败）。
- **可选组件（nginx/php/redis）**：安装完 MySQL 后依次交互询问「是否安装? [y/N]」，**直接回车=不安装**；选择安装时使用**当前发行版系统源可用的最新版本**（el8+ 为 nginx 1.2x / php 8.x / redis 7.x，老系统源版本较老但兼容）。Redis 密码默认 `gsgameshare.com`（对齐 .env REDIS_PASSWORD）。免交互可预置：`TLBB_OPT_NGINX=1 TLBB_OPT_PHP=1 TLBB_OPT_REDIS=1`（=0 或省略则不装，非交互模式下默认全不装）。离线模式下可选组件无内置离线包，会提示跳过。

### Debian 系
- **Ubuntu 12~17 / Debian 10**：EOL，走 old-releases / archive.debian.org 归档源，偶发不稳定，若失败建议改用 Docker 方案。
- **数据库（不用 MariaDB）**：
  - Ubuntu 12~16：系统源 MySQL 5.5/5.6
  - Ubuntu 18：系统源 MySQL 5.7
  - Ubuntu 20+：系统源 MySQL 8.0（Ubuntu 官方 mysql-server 即真 MySQL，非 MariaDB）
  - Debian 10+：**MySQL 官方 apt 源 8.0**（阿里云镜像 `mirrors.aliyun.com/mysql/apt/debian/`，Debian 的 mysql-server 元包是 MariaDB 别名，必须走官方源）
- **i386 多架构**：安装器会自动 `dpkg --add-architecture i386`，需要网络下载 i386 索引。
- **Debian 14~18**：截至当前未正式发布，安装器自动回退最新稳定版代号。

## 四、服务端注意事项

1. **服务端压缩包默认上传到 /root**，命名为 `tlbb.tar.gz` 或 `tlbb.zip`；也可执行 `untar /绝对路径/压缩包`。目标以 `TLBB_PATH` 为准，默认 `/tlgame/tlbb`；成功时打印实际路径，失败则保留原包与旧端。旧版误报成功的修复方法见 [untar 解压修复](untar-repair-20261104.md)。
2. **服务端位数**：ODBC 驱动必须与游戏进程位数匹配；原生版安装器会按服务端 ELF/系统架构选择驱动。EL10 使用 64 位端，不可让 32 位进程加载 64 位驱动，详见 [运行环境优化](runtime-defaults-20261103.md)。
3. **换端**：先停服并备份。`untar` 替换已有目录前保存到 `BACKUP_DIR/tlbb-before-untar-*.tar.gz`，原压缩包会重命名保留；`change` 在解压失败时中止，不继续重置数据库。确认新端正常后再清理备份。
4. **删档**：`reset` 会从环境包 `offline/sql/`（tlbbdb.sql / web.sql）重新导入初始库。
5. **数据库结构差异**：不同服务端版本的账号/点数表结构可能不同（t_account / account 等），`setvalid` / `setpoint` 若未生效，请以 tlbbdb.sql 中实际表结构为准。
6. **MySQL 8.0/8.4 数据库结构（3库/2库）**：安装时会交互询问（可 `TLBB_DB_LAYOUT=3|2` 预置，非交互默认 3 库）：
   - **3 库（新端/64位源端标准）**：`tlbbdb_10 + tlbbdb_main + web`，主库物理名为 `tlbbdb_main`（导入时自动改写 tlbbdb.sql 的 `CREATE DATABASE`/`USE` 头，tlbbdb.sql 原件保持不变）；`/etc/odbc.ini` 含 `tlbbdb_main`/`tlbbdb`/`tlbbdb_10`/`CHAR_DBTABASE` 四段 DSN。
   - **2 库（怀旧/经典端标准）**：`tlbbdb + web`，主库为 `tlbbdb`；`/etc/odbc.ini` 不含 `tlbbdb_10` DSN。
   - 5.7 及以下档位固定 2 库结构。若 3 库模式需切回 2 库：改 `TLBB_DB_LAYOUT=2` 重装，或手动 `CREATE DATABASE tlbbdb` 并将 tlbbdb_main 数据导出导入。
7. **MySQL 8.0 注意事项**：安装器已强制 `mysql_native_password` 认证并卸载 validate_password 组件（兼容 ODBC 3.51 / 老驱动）；8.0 需使用 64 位源端引擎，若为 32 位怀旧端请选 MySQL 5.1/5.7 档位（2 库结构）。
8. **SQL 导入兼容**：导入前目标库均已 `CREATE DATABASE IF NOT EXISTS` 先建好，导入时显式指定目标库（`mysql <库> < 文件`），因此**无论 SQL 文件是否自带 CREATE DATABASE/USE 头**都能正确导入（自带头幂等跳过，无头则落入指定库）。3 库模式主库 `tlbbdb_main` 用改写库名头的临时流导入，tlbbdb.sql 原件不变。
9. **可选组件离线包**：`download_offline.sh --full <el8|el9|el10>` 会额外下载 nginx/php/redis/unixODBC 到 `offline/rpm-packages/<branch>/{nginx,php,redis,odbc}/`（子目录），离线安装器按子目录识别安装并验证；老包若放在 `rpm-packages/<branch>/` 根目录同样兼容。**el10 注意**：官方 AppStream/EPEL 已无 redis 服务器包（RHEL 10 生态以 **Valkey 8** 替代，RESP 协议兼容），在线自动装 `valkey`、离线自动找 `valkey*.rpm`，端口 6379 与 `requirepass` 密码配置与 redis 完全一致，验证用 `valkey-cli -a <密码> ping`（兼容 `redis-cli` 用法）。
10. **makecache 失败排查**：查看 `/var/log/tlbb-packages.log` 区分 HTTP 404、DNS、TLS、超时或依赖冲突，不要仅凭下载字节数判断。CentOS Stream 9/10 的 Extras 使用 `SIGs/<版本>-stream/extras/$basearch/extras-common/`，不是 BaseOS 同级的 `extras/$basearch/os/`。模板保留独立国内镜像与官方后备地址；软件源全部不可用时中止安装并保留真实错误。在线一键引导默认在线，不会因 `/root/offline-el9.tar.gz` 等遗留文件切换模式；离线组件必须显式加 `--offline`。

## 五、常见问题（FAQ）

**Q1: 安装时提示「32 位兼容库安装不完整」？**
A: EOL 系统的 i686 包可能缺失，属正常现象。重点确认 glibc.i686 与 libstdc++.i686 已装（ODBC 驱动依赖），其余缺失不影响开服。

**Q2: isql 连接提示找不到驱动？**
A: 确认 `/usr/lib/libmyodbc3.so` 存在；检查 /etc/odbc.ini 中 Driver 路径与 /etc/odbcinst.ini 注册项。

**Q3: 服务端启动后端口未监听？**
A: 查看 `gslog` 日志；确认 ServerInfo.ini 中数据库 IP/密码与安装时一致（可 `setini` 重写）。

**Q4: 如何在完全离线的服务器安装？**
A: 将整个 src 目录（含 offline/ 全部组件）上传后执行 `bash install.sh`；离线时若 yum/apt 源不可用，安装器会跳过源配置，el5/6/7 的数据库与驱动由离线组件完成，el8+/deb 的数据库需在联网机器上离线下载 deb/rpm 后放入 offline 相应目录（`offline/rpm-packages/<elX>/mysql57|mysql80|mysql84/`、`offline/deb-packages/mysql80/`）。

**Q5: 与 Docker 版 gstlenv 有什么区别？**
A: 本包为原生安装（直接装到系统，无容器开销）；gstlenv 为 Docker 版参考项目。命令体系沿用 `gs` 原命令名（untar/setini/runtlbb/...），提供 `gsctl <命令> [参数...]` 统一入口，环境配置 `/root/.gs/.env`、数据目录 `/tlgame` 与 gstlenv 一致。默认端口保持兼容，密码不再使用固定值，而是独立生成 12 位随机值，见 [运行环境优化](runtime-defaults-20261103.md)。本项目问题请提交到 https://gitee.com/yulinzhihou/gstlenv_non_docker/issues 。
